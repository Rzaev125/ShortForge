# ShortForge для Windows

Первый рабочий сценарий — импорт локального видео. В окне можно выбрать файл или перетащить его из Проводника, посмотреть исходник и его метаданные, закрыть приложение и снова открыть сохранённый проект. Для неподдерживаемого кодека проигрыватель предлагает создать прокси. Интерфейс и обработка работают локально.

## Запуск

### Автокадр по лицу

Откройте клип в редакторе. В разделе «Кадр 9:16» выберите интервал анализа и нажмите «Автокадр по лицу». Интервал 250 мс даёт четыре наблюдения в секунду. Анализ использует исходное видео и встроенный детектор Windows, работает локально и допускает отмену. После сохранения можно посмотреть движение в редакторе, запустить точный предпросмотр или экспортировать MP4.

Камера следует за одним лицом и сбрасывает позицию на смене сцены. При кратком перекрытии она удерживает последнюю позицию. Сцены с несколькими людьми вписываются целиком. Кнопка «Зафиксировать этот кадр» сохраняет текущее кадрирование для всего клипа. В режиме «Заполнить» положение можно поправить вручную. «Вернуть автокадр» снова включает сохранённое движение. После изменения In/Out запустите анализ ещё раз.

### Пакетный экспорт

В проекте отметьте фрагменты в подборке или сохраните клипы в редакторе. В разделе «Пакетный экспорт» выберите, какие из них сохранить. Задайте частоту кадров, при необходимости включите SRT или манифест и нажмите «Выбрать папку и экспортировать».

Каждый клип получает отдельную подпапку с MP4. Если включён SRT, для него нужны фразы в интервале клипа. Манифест JSON содержит заголовок, интервал исходника, номер редакции, дорожку и фактический кодировщик. По умолчанию используется H.264/libx264, 30 кадров/с и нормализация громкости. Опция NVENC запускает пробное кодирование на этом ПК.

Во вкладке «Очередь» можно следить за ходом экспорта, отменить отдельное задание, повторить прерванное или открыть папку готового клипа. Если очередь сообщает о проблеме с доступом к хранилищу, восстановите доступ и нажмите «Возобновить очередь». После перезапуска ожидающие задания продолжаются. Если с момента постановки в очередь вы изменили монтаж, отправьте новую редакцию из проекта.

### Субтитры и сохранение клипа

Кнопка «Прослушать фразу» воспроизводит звук между началом и концом выбранной фразы. После правки времени нажмите её снова, чтобы услышать новые границы. Повторное нажатие во время воспроизведения останавливает фразу.

Откройте фрагмент в редакторе. В разделе «Субтитры» можно исправить текст и границы фразы, выбрать пресет, цвет, обводку, фон и положение. Время рядом с фразой отсчитывается от In клипа. «Точный предпросмотр» показывает до пяти секунд от курсора с титрами, которые отрисовал FFmpeg. После правки его можно создать снова.

«Сохранить MP4 с субтитрами» записывает целый клип в новый локальный MP4. «Сохранить SRT» записывает текст и время отдельно. Для рендера нужны доступный оригинал, FFmpeg с libass и ffprobe. Для SRT достаточно сохранённой редакции. Проверка времени отдельных слов описана в [отчёте P06](docs/P06_TIMING.md).

### Локальная расшифровка

Откройте проект с речью, выберите язык и дорожку в разделе «Расшифровка», затем нажмите «Распознать речь». Работающий процесс можно отменить. После завершения нажмите на фразу, чтобы перемотать проигрыватель к оценённому началу сегмента. Результат сохраняется вместе с проектом. Для той же дорожки, языка, модели и версии обработки используется сохранённая расшифровка. При недоступном оригинале ранее сохранённый текст можно читать в проекте.

На этом ПК установлены Windows x64 CLI whisper.cpp **v1.9.2**, многоязычная модель **small** и детектор речи **Silero v6.2.0**. В дереве проекта CLI с DLL находится в `tools/bin/whisper-v1.9.2/Release/`, обе модели — в `models/`. Приложение находит их при запуске сборки из дерева ShortForge. Для отдельной установки положите каталог `tools/whisper-v1.9.2/Release/` и папку `models/` рядом с EXE либо укажите их общий каталог в переменной `SHORTFORGE_ASR_HOME`. Загрузки выполняются вручную. Файлы речи обрабатываются на CPU.

| Файл | Источник | SHA-256 |
|---|---|---|
| whisper-bin-x64.zip (8,2 МБ) | [Релиз 1.9.2](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.2) | `49dcc16de826f20bd53d44f947a1ae49dfa81f86cad67a64d80820cb192d674a` |
| ggml-small.bin (488 МБ) | [Многоязычная модель](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-small.bin) | `1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b` |
| ggml-silero-v6.2.0.bin (885 КБ) | [Детектор речи](https://huggingface.co/ggml-org/whisper-vad/blob/main/ggml-silero-v6.2.0.bin) | `2aa269b785eeb53a82983a20501ddf7c1d9c48e33ab63a41391ac6c9f7fb6987` |

### Открыть приложение

На этом компьютере откройте `artifacts\publish\ShortForge.exe`. Можно начать с технического ролика `artifacts\fixtures\Тест O'Brien\цвет и тон.mp4`. Список проектов при первом запуске пуст.

Из исходников, в PowerShell из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Run.ps1
```

В «Настройках» видны версии инструментов. Если ffprobe отсутствует, нажмите «Выбрать папку» и укажите каталог с `ffprobe.exe` и `ffmpeg.exe`. Для импорта достаточно первого, для миниатюр и прокси нужен второй. Приоритет поиска — сохранённый выбор, `SHORTFORGE_FFMPEG_BIN`, папка `tools` рядом с EXE, затем PATH. Для локальной разработки Run.ps1 указывает на `tools\bin`.

## Сборка и проверка

Для сборки помощника `ShortForge.FaceDetector.exe` нужны Visual Studio Build Tools с компонентом MSVC x64/x86 и Windows 11 SDK 10.0.26100.0. Готовая сборка уже включает помощник. Он использует компонент Windows.Media.FaceAnalysis на компьютере пользователя. [Подробности о детекторе](docs/P08_DETECTOR.md)

Если выбранная вручную папка исчезла или её настройка повреждена, откройте «Настройки» и нажмите «Включить автоматический поиск». ShortForge перечитает доступные инструменты и покажет их версии. После этого можно сразу повторить импорт.

Нужны Windows x64, .NET SDK 10.0.404 x64, Node.js 24 и npm. Для открытия окна нужны Windows Desktop Runtime .NET 10 x64 и Evergreen WebView2. На проверенном ПК всё это уже установлено. Для восстановления пакетов нужны nuget.org и registry.npmjs.org. При обычном запуске Node, Vite и доступ к сети не требуются.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Check-Environment.ps1 -Media -FFmpegBin .\tools\bin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\New-TestMedia.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1
dotnet test ShortForge.slnx -c Release --no-build --no-restore
npm.cmd --prefix src/ShortForge.Ui test
npm.cmd --prefix src/ShortForge.Ui run test:browser
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Windows.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Publish.ps1
```

Build.ps1 выполняет `npm ci`, строгую проверку TypeScript и сборку Vite, затем `dotnet restore --locked-mode` и сборку solution. При изменении интерфейса сначала пересоберите UI. Publish.ps1 складывает framework-dependent сборку win-x64 в `artifacts\publish`, вместе с локальным UI и, если они подготовлены в `tools\bin`, FFmpeg, ffprobe и их лицензией. Переносится вся папка. Для технических интеграционных тестов положите оба инструмента в `tools\bin` либо добавьте их в PATH. Проверяйте в отчёте число пропущенных тестов.

Проверить только браузерную вёрстку можно командой `npm.cmd --prefix src/ShortForge.Ui run dev`. Браузерный режим показывает отсутствие подключения к Windows. Обычное окно работает с собранной папкой `ui`. Реальные результаты Windows-проверок и ограничения приведены в [STATUS.md](STATUS.md).

### Предпросмотр HDR (F11)

Откройте проект с HDR-видео. Если WebView2 поддерживает исходник, сразу доступен прямой просмотр. Для просмотра в SDR нажмите «Создать SDR-прокси». При нескольких звуковых дорожках сначала выберите нужную в списке. Копия H.264 сохраняется для следующего открытия проекта. Поддерживаются PQ и HLG с первичными цветами BT.2020, матрицей BT.2020 NC и указанным диапазоном сигнала. Для других HDR-меток и Dolby Vision под проигрывателем указано ограничение. Выбранная локальная сборка FFmpeg должна содержать zscale, tonemap и libx264, для копии со звуком также AAC.

После Release-сборки запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Hdr.ps1`. Проверка создаёт три локальных технических ролика с метками PQ, HLG и BT.709, сравнивает их с выводом ffprobe и открывает проекты в двух процессах WPF. Файлы, снимки окна и результаты остаются в `artifacts/smoke/hdr-*`.

### Интервалы кадров исходника

В разделе «Сведения об исходнике» кнопка «Измерить интервалы кадров» показывает, сколько миллисекунд проходит между первыми кадрами видео. Для измерения нужны оригинал и ffprobe. Если открыт прокси, программа всё равно читает оригинал. Результат для первых 48 кадров (или меньшего числа в короткой записи) сохраняется в SQLite и доступен после переноса исходника. Интервалы в других частях длинной записи могут отличаться.

### Восстановление предпросмотра

Если проигрыватель сообщает, что сохранённый прокси не воспроизводится, нажмите «Повторить». При повторной ошибке нажмите «Пересоздать прокси». Для этого нужен доступный оригинал и локальные ffmpeg/ffprobe. Если исходник перемещён, сначала укажите его через «Найти файл». Проверка сценария после Release-сборки — `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Vfr.ps1 -RepairProxy`.

### Выбор звука для предпросмотра (F11)

Откройте видео с несколькими звуковыми дорожками. Под проигрывателем выберите номер дорожки в поле «Звуковая дорожка для прокси». Рядом с номером видны название, язык и кодек, если они есть в файле. Нажмите «Создать прокси». Для смены звука выберите другую дорожку и нажмите «Применить дорожку». Первый выбор каждой дорожки требует локального кодирования. Готовые копии используются повторно, а выбранная дорожка сохраняется при закрытии проекта.

Если исходник перенесён, откройте проект и выберите дорожку с сохранённым прокси. Такой выбор работает и без FFmpeg. Рядом с остальными дорожками появится пометка «нужен исходник». Кнопка «Найти файл» позволяет указать новое расположение оригинала.

После Release-сборки запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AudioTracks.ps1`. Скрипт создаёт шестисекундный MKV с тремя тонами (440, 880 и 660 Гц) и делает прокси для первых двух дорожек. В трёх процессах WPF он проверяет частоту декодированного звука, выбор после перезапуска, доступность дорожек при потере файлов и восстановление связи с оригиналом. Журналы, снимки и тестовое видео остаются в `artifacts/smoke/f11-*`.

### Проверка длинного видео (F06)

После Release-сборки запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-LongVideo.ps1` на рабочем столе Windows. Скрипт создаёт 30-минутный MKV с тестовым изображением и тоном, импортирует его в отдельный профиль и отменяет создание прокси в «Очереди». Затем он повторяет кодирование, проверяет перемотку и открывает сохранённый проект во втором процессе. Для ручного просмотра исходник и прокси остаются в новом каталоге `artifacts/smoke/f06-*`. На проверенном ролике они заняли вместе около 222 МиБ плюс место для профиля WebView2. Там же находятся события FFmpeg, счётчики памяти, журналы и контрольные суммы.

### Проверка поворота и времени кадров (F05)

Для проверки своей короткой телефонной записи с квадратными пикселями и звуком выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-PhoneVideo.ps1 -Source "D:\Видео\запись.MOV"`, подставив фактический локальный путь. Скрипт измеряет интервалы кадров и открывает файл в отдельной библиотеке WPF, затем повторяет проверку после перезапуска. Если оригинал воспроизводится, в журнал попадают размеры кадра, результаты перемотки и сравнения изображения и звука с независимым декодированием FFmpeg. При недоступном прямом просмотре проверяется доступный прокси либо сообщение об ограничении HDR. Кадры и фрагменты звука для сравнения обрабатываются в памяти. Локальный профиль приложения в `artifacts/smoke/phone-*` содержит обычную тестовую SQLite-библиотеку.

Для видео с неквадратными пикселями откройте «Сведения об исходнике». Там показаны пропорции пикселя и, при наличии метаданных, пропорции кадра до поворота. Новые миниатюры сохраняются как JPEG с квадратными пикселями. Чтобы проверить этот сценарий на повёрнутом VFR-видео, после Release-сборки выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Vfr.ps1 -Anamorphic`. Проверка сопоставляет геометрию прямого просмотра, прокси и миниатюр, сверяет отметки кадров и повторно открывает проект в отдельном процессе.

После Release-сборки запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Vfr.ps1`. Скрипт создаёт два коротких MOV с переменными интервалами между кадрами и поворотом 90°. В отдельном профиле WPF он проверяет прямой просмотр, создание прокси и кнопку «Обновить прокси» для проекта предыдущей версии. В `artifacts/smoke/f05-*` остаются оба исходника, прокси, снимки окна и покадровые отчёты ffprobe.

### Проверка импорта видео больше 1 ГиБ (B06)

После Release-сборки запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-LargeImport.ps1`. Понадобится примерно 1,2 ГБ свободного места плюс место под отдельный профиль WebView2. Скрипт локально создаёт MP4 с настоящими кадрами H.264. В окне приложения он отменяет импорт во время проверки SHA-256, повторяет его и проверяет воспроизведение и перемотку. Журнал, метаданные ffprobe и измерения памяти сохраняются в новом каталоге `artifacts/smoke/b06-*`. Сгенерированные видео удаляются при выходе. Ключ `-KeepMedia` оставляет их для повторного просмотра.

### Проверка системного DPI

Для приёмки P01 на дисплее с масштабом Windows 125% запустите первую команду. На дисплее с масштабом 150% запустите вторую. Каждый прогон открывает окна 1280×800 и 1440×900, проверяет DPI окна и диалога выбора файла, оставляет ZoomFactor равным 1 и сохраняет фактические измерения в `artifacts/smoke`. При несовпадении масштаба команда завершается с ошибкой. Параметры дисплея скрипт только читает. Для контрольного прогона на дисплее 100% укажите `-NativeDpiPercent 100`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Windows.ps1 -NativeDpiPercent 125
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Windows.ps1 -NativeDpiPercent 150
```

## Локальные данные

| Путь от `%LOCALAPPDATA%\ShortForge` | Содержимое |
|---|---|
| `library.sqlite3` | Проекты, исходный путь, SHA-256, параметры файла и JSON ffprobe |
| `thumbnails\`, `proxies\` | Производные файлы с именами по ID |
| `tools.json` | Папка инструментов после выбора в настройках |
| `webview\`, `logs\` | Профиль встроенного проигрывателя и коды ошибок |

Исходник остаётся по выбранному пути. Если файл перемещён или его размер либо дата изменения отличаются, откройте проект и нажмите «Найти файл». Приложение проверит совпадение SHA-256 до смены пути. При импорте и строгой проверке хеш читается потоком, поэтому на больших файлах скорость диска влияет на время операции.

## Подбор фрагментов

После распознавания откройте «Подбор фрагментов», задайте длительность и нажмите «Найти фрагменты». По умолчанию это 30–60 секунд и до 10 предложений. «Посмотреть фрагмент» воспроизводит интервал до его конца. Для многодорожечного видео подготовьте прокси со звуком дорожки расшифровки. Проект сохраняет последний успешный подбор для каждой расшифровки.

Нажмите «Послушать границы», чтобы проверить первое и последнее слово. Проигрыватель покажет первые и последние три секунды. Если фрагмент короче или равен шести секундам, прозвучит весь фрагмент.

Отметьте подходящие фрагменты флажком «Выбрать». Кнопка «Отклонить» перемещает фрагмент в список отклонённых. Там его можно вернуть. Новый успешный поиск заменяет текущую подборку для этой расшифровки.

«По структуре речи» работает локально по предложениям, паузам и длительности. В режиме «Смысловой анализ» ShortForge обращается к Ollama на этом компьютере. Нужна запущенная Ollama с локальной моделью `qwen2.5-coder:7b`, манифест `dae161e27b0e90dd1856c8bb3209201fd6736d8eb66298e75ed87571486f4364`. Объём весов 4,68 ГБ, лицензия Apache 2.0. Если модели ещё нет, пользователь может самостоятельно скачать её командой `ollama pull qwen2.5-coder:7b`. Установленные модели показывает `ollama list`. [Карточка модели и лицензия](https://ollama.com/library/qwen2.5-coder:7b)

Для локального запуска в PowerShell задайте `$env:OLLAMA_NO_CLOUD='1'`, затем `$env:OLLAMA_HOST='127.0.0.1:11434'` и выполните `ollama serve`, если Ollama ещё не запущена. Нестандартный порт задаётся в окружении ShortForge через `SHORTFORGE_OLLAMA_PORT`. Приложение проверяет локальный манифест и передаёт текст и метки сегментов только на 127.0.0.1. Оценки 0–4 отражают суждение модели по каждому признаку. При ошибке сохраняется предыдущая подборка. [API Ollama](https://docs.ollama.com/api/chat)
