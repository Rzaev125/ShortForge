Ты работаешь над новым проектом ShortForge — локальным Windows-приложением для превращения длинных разговорных видео в вертикальные shorts с субтитрами. Пользователь утвердил концепцию и стек. В папке сейчас пакет требований, а не готовое приложение.

Прочитай AGENTS.md, README_FIRST_RU.md, STATUS.md, PLANS.md, docs/PRODUCT_SPEC.md, docs/ARCHITECTURE.md, docs/DESIGN_SPEC.md, docs/SETUP_WINDOWS.md и docs/ACCEPTANCE.md.

Не ограничивайся пересказом плана. Начни реализацию P00, затем P01 и P02 по мере прохождения проверок. Результат этого первого блока: реальное Windows-приложение с современным интерфейсом, выбором локального видео, реальными метаданными ffprobe, созданием проекта в SQLite и превью либо честным сообщением о необходимости прокси.

1. Проверь ОС терминала, фактическую папку, git status, .NET SDK, Node/npm, Git, WebView2 и FFmpeg. У меня раньше была .NET 9 и уже есть Docker; ничего не переустанавливай и не удаляй вслепую. Для проекта используем .NET 10 SDK x64. Docker не нужен.
2. Создай предлагаемую структуру solution и React UI из ARCHITECTURE. Уточни совместимые стабильные версии зависимостей по официальным источникам, закрепи их. Воспроизводимые build/run/check команды запиши в README разработки.
3. Построй настоящий WPF/WebView2 host и типизированный мост с проверкой origin и схемы. В production загружай собранный локальный UI, без Vite-сервера и внешних CDN.
4. Реализуй основной экран и пустые состояния по DESIGN_SPEC. Не создавай фиктивные проекты и результаты. Операции, которых пока нет, показывай недоступными с понятным объяснением.
5. Подключи ffprobe, SQLite и реальный импорт. Не передавай большие видео через JavaScript. Исходник не меняй. Подготовь небольшой технический тестовый ролик, если FFmpeg доступен; он не заменяет проверку на настоящей речи.
6. Проверь сборку, ошибки файлов, пути с пробелами/кириллицей и сохранение проекта после перезапуска. Проверь окно в Windows. Если ты работаешь в Linux/WSL, не называй приложение проверенным до отдельного Windows-smoke-test.
7. Обнови STATUS.md, PLANS.md и docs/DECISIONS.md. Перечисли реально завершённые проверки и оставшиеся ограничения.

Если не хватает системного SDK или runtime, объясни конкретно что установить и как проверить. Продолжай независимые части, но не выдавай отсутствие проверки за успех. Рутинные решения принимай самостоятельно. Не подключай платные API и не отправляй мои видео или расшифровки в облако.

Не реализуй весь видеоредактор одним огромным изменением. После P00–P02 дай проверяемый результат, инструкции запуска и точный следующий шаг P03. Не обещай готовность распознавания, ИИ-выбора или экспорта, пока они не реализованы.
