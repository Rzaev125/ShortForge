# Подготовка Windows к работе в Codex

## 1. Папка

Создай `D:\Projects\ShortForge` либо другую короткую локальную папку.
Распакуй **содержимое** папки из архива туда. Проверь, что `AGENTS.md` лежит прямо
в выбранном корне проекта, а не на два уровня глубже. Для старта лучше путь без OneDrive.
Тесты кириллицы всё равно обязательны; короткий путь упрощает первоначальную диагностику.

## 2. Установить для начала

| Что | Что выбрать | Зачем |
|---|---|---|
| .NET | .NET 10 **SDK**, Windows **x64**, стабильная обслуживаемая версия | Сборка C#/WPF |
| Node.js | 24 LTS, Windows x64 MSI; npm входит в установку | Сборка React UI |
| C++ и Windows SDK | Visual Studio Build Tools, компонент MSVC x64/x86 и Windows 11 SDK 10.0.26100.0 | Сборка помощника для обнаружения лиц из исходников |
| Git | Git for Windows x64, если отсутствует | История изменений |
| WebView2 | Evergreen Runtime x64, если отсутствует | Интерфейс внутри Windows-окна |
| Codex | Твой локальный Codex с доступом к папке | Работа агента над кодом |

.NET Runtime и SDK — разные вещи. Наличие .NET 9.0.12 не подтверждает установленный SDK.
Существующую .NET 9 удалять не надо: версии могут стоять рядом.
Проект намеренно использует .NET 10 LTS, а не автоматически самую новую major-версию.
В `global.json` Codex должен закрепить реально установленный совместимый SDK 10.x.

Ссылки:
- [.NET 10 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)
- [Node.js](https://nodejs.org/en/download/) — выбрать ветку 24 LTS.
- [Git for Windows](https://git-scm.com/downloads/win)
- [WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)

Visual Studio целиком не обязателен для CLI-сборки через .NET SDK.
Если пользуешься Visual Studio, нужна версия с поддержкой выбранного SDK и workload
“.NET desktop development”. VS Code/Rider — по желанию, не обязательная часть этого пакета.
Python, CUDA Toolkit, CMake и Docker для начального этапа не нужны.
CUDA Toolkit/CMake могут понадобиться позже только если принято решение собирать native tools из исходников.

После установки закрой и заново открой терминал/Codex, чтобы обновился PATH.

## 3. Проверить

В Windows PowerShell в папке проекта:

```powershell
dotnet --list-sdks
node --version
npm.cmd --version
git --version
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Check-Environment.ps1
```

`ExecutionPolicy Bypass` здесь действует только для запуска этого процесса;
скрипт ничего не устанавливает и не меняет постоянные политики.
Если управляемый корпоративный ПК запрещает запуск, не обходи организационные настройки:
достаточно выполнить отдельные команды вручную и показать вывод Codex.

Ожидается SDK `10.0.xxx`, Node `v24.x`, версия npm и Git. Скрипт использует английские
сообщения, чтобы работать и в Windows PowerShell 5.1 без проблем кодировки.
WebView2 определяется эвристически по каталогам; окончательная проверка — запуск host.

Если `npm.ps1` блокируется ExecutionPolicy, вызывай `npm.cmd`, не меняй политики всей системы.
Если виден только .NET Runtime — установи SDK. Если SDK 10 установлен, но `dotnet --version`
показывает другой — проверь `global.json` родительских папок и путь `where.exe dotnet`.

## 4. FFmpeg — нужен к P02

Начни с [официальной страницы FFmpeg](https://ffmpeg.org/download.html), раздел Windows EXE.
Она ссылается на Windows-сборки, например gyan.dev/BtbN. Выбирай стабильный x64-пакет,
содержащий `ffmpeg.exe`, `ffprobe.exe`, H.264/AAC и фильтр `subtitles` с libass.
Версии не угадывать по старым блогам; записать полученную версию в отчёт.

Можно распаковать в `D:\Tools\ffmpeg`, где будет `bin\ffmpeg.exe` и `bin\ffprobe.exe`.
Добавление в глобальный PATH не обязательно — приложение будет принимать путь в настройках.

```powershell
& 'D:\Tools\ffmpeg\bin\ffmpeg.exe' -version
& 'D:\Tools\ffmpeg\bin\ffprobe.exe' -version
& 'D:\Tools\ffmpeg\bin\ffmpeg.exe' -filters | Select-String 'subtitles'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Check-Environment.ps1 -Media -FFmpegBin 'D:\Tools\ffmpeg\bin'
```

Сначала CPU-экспорт libx264. Поддержку NVENC на конкретной видеокарте/сборке/драйвере
проверять маленьким реальным encode; наличие имени encoder не является достаточной проверкой.
Не обновляй драйвер и не ставь CUDA Toolkit просто ради начала проекта.

## 5. whisper.cpp — нужен к P03

Источник: [официальный репозиторий](https://github.com/ggml-org/whisper.cpp), раздел Releases.
Брать Windows x64 CLI и соответствующие runtime-файлы из проверенного release.
Начать с CPU-совместимого варианта; ускорение подключать после измерения.
Имена архивов/EXE могут меняться — Codex должен проверить release и `--help`, а не угадывать.

Отдельно потребуется многоязычная модель, например `small` (не `.en`, если нужен русский).
Скачивать по инструкции `models` выбранной версии whisper.cpp, проверить источник,
размер и опубликованный checksum при наличии. Не переименовывать произвольный файл в .bin.

Предлагаемые каталоги:
- `D:\Tools\whisper\` — CLI и его runtime-файлы.
- `D:\AI\Models\whisper\` — модели.

Пути в этих примерах рекомендательные. Не создавать их на другом компьютере удалённо;
настроить фактические пути пользователя. Модели и бинарники не коммитить в git.

## 6. Смысловой ИИ — позже, к P04

Для запуска приложения/импорта API-ключ не нужен. Распознавание локальное.
Сначала можно строить кандидатов по структуре речи, затем подключить проверенный
локальный LLM. Его модель выбирается по реальной RAM/VRAM и качеству на твоих роликах.
На GTX 1660 Super не обещать скорость больших моделей и одновременную работу всех ИИ на GPU.
CPU fallback и последовательный запуск обязательны.

Облачный вариант — отдельная опция: провайдер, ключ, лимит расхода, явное разрешение
передачи расшифровки. Не сохраняй ключ в START_CODEX.txt, AGENTS.md или переписку с кодом.

## 7. Диск и тестовое видео

После установки инструментов желательно иметь хотя бы 20–30 ГБ свободно для первых тестов,
плюс объём исходников/прокси/экспортов. Это запас, а не фиксированное системное требование.
Длинные 4K-видео требуют больше; Codex должен измерять реальный расход.
Не удаляй оригиналы после импорта — проект по умолчанию хранит ссылку на исходник.

Начни с собственного ролика 2–5 минут, затем 30–60 минут. Для технического smoke-test
Codex может сгенерировать короткий тестовый клип FFmpeg, но он не заменяет речевую проверку.

## 8. Запуск разработки

1. Открыть папку в Codex с возможностью выполнять команды на локальном Windows.
2. Отправить полный START_CODEX.txt.
3. Codex проверит среду и создаст solution/UI/скрипты запуска.
4. Использовать команды запуска, которые он реально проверил и записал в README.

Для реализованного блока P00–P02 команды приведены в [README разработки](../README.md).
Пакет React находится в `src/ShortForge.Ui`. Выполняйте `scripts/Build.ps1` из корня проекта.
Существующий Docker никак не участвует: контейнер Linux не заменяет Windows/WPF runtime.

Если агент работает в облачной Linux-среде, он может писать core/UI и тестировать их,
но финальный запуск Windows-окна нужно выполнить локально. Не подменять стек из-за среды.
