### 20 ноября 2026 · локальное кадрирование по лицу

Для P08 выбран встроенный Windows.Media.FaceAnalysis.FaceDetector. FFmpeg выбирает уменьшенные кадры исходника с учётом поворота и соотношения сторон пикселя. Собственный адаптер C++/WinRT передаёт в C# прямоугольники лиц и признак смены плана. Детектор обслуживается вместе с Windows. При недоступности компонента пользователь видит ошибку и может кадрировать вручную. [Состав, версии и ограничения](P08_DETECTOR.md)

Положение кадра хранится в SQLite в монтажном решении клипа. Время точек отсчитывается от In. Между точками одного плана положение интерполируется с ограничением скорости. При кратком перекрытии камера удерживается до 750 мс. При нескольких лицах в одном плане используется общий статический кадр. Для определения говорящего потребовался бы отдельный аудиовизуальный анализ. Ручной режим сохраняется при открытии и экспорте, а изменение границ сбрасывает прежнюю траекторию.

Точный предпросмотр и оба пути экспорта строят фильтр FFmpeg из сохранённых точек и редакции клипа. FFmpeg читает длинное выражение из временного файла, что позволяет обработать все 3600 точек на Windows. Браузер получает траекторию для отображения, а расчёт и запись принадлежат хосту. ### 20 ноября 2026 · P04, выбор и проверка фрагментов

- Режим «По структуре речи» использует границы предложений, паузы и диапазон длины. Он доступен без модели. В обоих режимах C# задаёт длительность по оригинальной шкале ASR, исключает пересечения и одинаковые цитаты. Количество предложений ограничено сверху.
- Для первого смыслового режима использована уже установленная Qwen 2.5 Coder 7B Q4_K_M (4,68 ГБ, Apache 2.0). Ollama работает через фиксированный IPv4 loopback. Клиент отключает прокси и редиректы, проверяет digest модели, вызывает только список моделей и локальный чат. Причина выбора модели — возможность проверить имеющиеся веса на этом ПК. Сравнение с правилами хранится в [листе приёмки](P04_REVIEW.md). [Модель](https://ollama.com/library/qwen2.5-coder:7b) · [Формат структурного ответа](https://docs.ollama.com/capabilities/structured-outputs)
- В первом прогоне свободный выбор начального и конечного ID дал недопустимую пару. Теперь хост передаёт модели список разрешённых пар. Ответ ограничен схемой JSON и повторно проверяется в C#. Заголовок — цитата из выбранного места. Причина — одна из трёх редакторских категорий. Четыре оценки 0–4 показаны под раскрываемым заголовком как оценки модели.
- Текст передаётся отдельно от системных инструкций. Длинные расшифровки разбиваются на окна с перекрытием. Если окно не вмещает минимальную допустимую длину для части исходника, приложение сообщает об ограничении контекста и сохраняет прежнюю подборку.
- Схема SQLite 6 хранит последний успешный набор вместе с активной расшифровкой. Выбор, отклонение и возврат привязаны к ID конкретной подборки. Неудачный запрос и отмена до фиксации не заменяют сохранённые предложения. При повреждении оценок отбрасывается только подборка.

### 20 ноября 2026 · SDR-предпросмотр PQ и HLG (P02)

### 20 ноября 2026 · Измерение интервалов в начале исходника (P02)

Пользователь запускает измерение в сведениях об исходнике. После проверки SHA-256 ffprobe читает основной видеопоток, выбранный по тем же правилам, что и при импорте. Для ограничения нагрузки заданы 96 входных пакетов, до 48 декодированных кадров и тайм-аут 30 секунд для покадрового запроса. Окно указывает область измерения и количество кадров. Классификация всего ролика как CFR или VFR потребовала бы проверки остальной записи. При измерении запрашиваются только `frame=pts:stream=time_base` в построчном формате ffprobe. Это исключает большой вывод вложенных HDR-данных, обнаруженный на телефонном MOV. На повёрнутом VFR-исходнике с SAR 5:4 проверены изображение в WebView2, квадратный пиксель производных файлов и совпадение временных отметок. Проверка с телефонной записью учитывается отдельно. [Результаты](../artifacts/smoke/f05-391b16a1022043cea3a5f766dc4b48a8/results.txt)

### 20 ноября 2026 · Цветовые метаданные исходника и доступность SDR-прокси (P02)

Окно проекта читает цветовые характеристики из JSON ffprobe, уже сохранённого в SQLite. Для чтения этих сведений и обработки используется один способ выбора видеопотока с учётом флага default и обложек. Список проектов по-прежнему загружается без чтения JSON всех файлов. Повреждение сохранённого JSON оставляет доступными путь и основные сведения о проекте. Для создания новой копии библиотека проверяет реальный исходник через ffprobe.

Для HDR-признаков, распознаваемых библиотекой, интерфейс заранее объясняет ограничение SDR-прокси. Оригинал передаётся штатному проигрывателю. Один лишь охват BT.2020 допускает создание прокси. В F11 проверены PQ и HLG, контрольный 10-битный SDR и сохранность файлов. Оценка физической яркости и цветопередачи дисплея требует отдельной проверки. [Результаты F11](../artifacts/smoke/hdr-25808727560b473ea69b1faa2b83e074/results.txt)

### 20 ноября 2026 · Выбор звука у прокси с несколькими дорожками (P02)

Пользователь выбирает дорожку для предпросмотра. Номера в интерфейсе начинаются с 1. Названия, язык и кодек берутся из сохранённых метаданных ffprobe. В запросе к host передаётся порядковый номер среди аудиопотоков с отсчётом от 0. Host проверяет тип и диапазон, FFmpeg получает явный `-map 0:a:N`. Для первого прокси начальным выбором остаётся первая дорожка, включая файлы с другой дорожкой по умолчанию. Выбор для ASR и экспорта относится к их собственным этапам.

Схема SQLite версии 3 хранит по одному действующему ID прокси на сочетание проекта и дорожки. Миграция привязывает прежние прокси из схемы 2 к первой дорожке, которую кодировала предыдущая версия приложения. Для видео без звука та же запись кэша обозначает единственную немую копию. При новом кодировании активная ссылка меняется транзакцией после проверки результата ffprobe. Каждая копия получает отдельный локальный URL для запросов диапазонов WebView2. При возврате к готовой дорожке приложение переключает ссылку на существующий файл. [Проверка воспроизведения и повторного запуска](../artifacts/smoke/f11-deec08ced3864975b726f3fddd62545d/results.txt)

### 20 ноября 2026 · Декодирование видео и прогресс прокси (P02)

После события `loadedmetadata` проигрыватель проверяет наличие изображения по `videoWidth`. Это учитывает контейнеры, в которых WebView2 распознал аудиодорожку, но пропустил видеопоток. При нулевой ширине пользователь получает возможность создать локальный прокси. Поведение воспроизведено на FFV1/PCM в MKV.

Во время кодирования процент вычисляется по `out_time_us` из потока прогресса FFmpeg и длительности исходника по ffprobe. До завершения кодирования интерфейс показывает до 99%. Затем отображается отдельный этап проверки файла. Готовый прокси становится доступным после проверки ffprobe и сохранения ссылки в SQLite. [События реального прогона](../artifacts/smoke/f06-38ad7f635879436a8742debe6b111d38/stages.json)

### 20 ноября 2026 · Временная база прокси при VFR (P02)

FFmpeg получает `-fps_mode:v passthrough -enc_time_base:v demux`. Первый параметр сохраняет последовательность кадров, второй задаёт кодировщику временную базу входного потока. Ранее при округлении к сетке частоты кадров максимальная разница в тесте достигала 11 762 мкс. После исправления совпали все 50 отметок и длительность. Поворот из display matrix применяет FFmpeg при декодировании; повторно поворачивать плеер средствами CSS не требуется. [Покадровая проверка](../artifacts/smoke/f05-7ef2153bdc40440aa6666199d3fd882c/results.txt)

Для новых копий используется имя `<id>.v2.mp4`. SQLite продолжает хранить ID прокси. Файл прежнего формата остаётся пригодным для просмотра. При доступном оригинале пользователь может обновить копию из проекта. Новая запись становится активной после ffprobe и фиксации транзакции. Предыдущий файл сохраняется в кэше, в том числе для проектов, где он мог быть импортирован как исходник.

### 20 ноября 2026 · Большие исходники в WebView2 (P02, B06)

При открытии большого MP4 Chromium запрашивает открытый диапазон с начала файла. Для внутренних маршрутов `/media` и `/proxy` host отдаёт за один GET максимум 2 МиБ с точным Content-Range и полной длиной файла в заголовке диапазона. Проигрыватель запрашивает продолжение самостоятельно. HEAD возвращает размер без тела. Для полного GET медиа больше 2 МиБ без Range внутренний маршрут отвечает HTTP 400. Это ограничение действует в слое предпросмотра; нативный FFmpeg по-прежнему читает исходник с диска.

Процент при импорте относится к прочитанным байтам на этапе SHA-256. Для ffprobe, миниатюры и записи SQLite интерфейс показывает название операции. [Прогон B06](../artifacts/smoke/b06-bb2c669147034f07a43d2c140c70d758/large-import.txt)

### 20 ноября 2026 · Оригинал для обработки и прокси для просмотра

Сохранённый прокси можно смотреть в проекте, пока пользователь восстанавливает связь с перенесённым исходником. Для запуска обработки по ID проекта библиотека читает из SQLite исходный путь, размер и SHA-256. Она проверяет файл и держит его открытым с FileShare.Read на время чтения FFmpeg. Файл из кэша не участвует в выборе источника обработки.

Пользователь подтвердил сохранение действующего критерия P02 до появления финального экспортёра P07. Контрольный рендер проверяет вход FFmpeg после перезапуска. Сквозная приёмка P07 должна отдельно проверить итоговый файл, созданный пользовательской командой экспорта. [Проверки P02](../STATUS.md)

### 20 ноября 2026 · Диагностика кодировщиков и приёмка P01

Для строки «Кодировщики прокси» host запрашивает у выбранного FFmpeg список через `-hide_banner -encoders`. Для существующей команды прокси важны точные имена видеокодировщика `libx264` и аудиокодировщика `aac`. Если список недоступен, интерфейс показывает «Не проверены». Диагностика не читает пользовательское видео. Успешность конкретного прокси по-прежнему определяется кодированием и проверкой результата через ffprobe.

Для A03 приняты прогоны на одном физическом мониторе с переключением штатного масштаба Windows. У WPF и системного диалога измерены 120 и 144 DPI при ZoomFactor WebView2 = 1. После восстановления масштаба приложение измерило 96 DPI. [Протокол приёмки](../STATUS.md)

### 20 ноября 2026 · Фокус после отмены диалога (P01)

Пока открыт системный диалог выбора видео, повторный импорт заблокирован. WebView2 при отключении кнопки сбрасывает фокус на документ. Интерфейс запоминает кнопку перед операцией и возвращает фокус после разблокировки, если пользователь остался на том же экране, кнопка ещё доступна и фокус свободен. Windows smoke закрывает только диалог своего окна и повторяет выбор клавишей Enter. [Прогон в WPF](../artifacts/smoke/5987a9f00275437aa7adb92adce7ec9d/import.txt)

### Решения по проекту

| Решение | Причина |
|---|---|
| Windows desktop для личного использования | Выбор пользователя |
| C#/.NET 10 + WPF/WebView2 + React | Соответствует опыту пользователя; отделяет UI и обработку |
| FFmpeg/ffprobe | Обработка разных контейнеров/кодеков и единый export pipeline |
| whisper.cpp | Локальная ASR с CPU fallback; GPU только после проверки |
| SQLite | Локальные проекты/очередь без отдельного сервера |
| Без Docker на первой версии | Для WPF desktop и child-process pipeline он не нужен |
| Ручная правка обязательна | ASR, подбор моментов и crop могут ошибаться |
| Локальный режим по умолчанию | Видео не требуется загружать на сервер |
| Облачный LLM только опционально | Отдельные расходы и явный выбор передачи текста |
| Речь как первая специализация | Для игр/видео без речи нужен другой анализ |
| Прямой upload на платформы позже | MVP экспортирует файлы, пользователь публикует сам |
| Подготовка только пакета документов в этом запросе | Последнее уточнение пользователя |

## Новые решения

### 20 ноября 2026 · восстановление инструментов в P01

ShortForge сохраняет явно выбранную папку до решения пользователя. При недоступной папке или повреждённом `tools.json` из «Настроек» можно включить автоматический поиск. Типизированная команда принимает пустой payload и сбрасывает только выбор папки в текущем профиле ShortForge. Диагностика сверяет вывод `-version` с ожидаемой программой. Во время восстановления тест запускает настоящие ffprobe и FFmpeg в изолированном профиле и затем импортирует видео.

### 20 ноября 2026 · навигация и приёмка P01

- При возврате из рабочей области библиотека восстанавливает фокус по ID проекта. При завершении фоновой операции данные проекта обновляются всегда. Перейти в его рабочую область можно автоматически, пока пользователь остаётся в разделе, из которого начал операцию. Первичная загрузка диагностики в открытом разделе настроек работает параллельно с обработкой медиа.
- Для A03 у Windows smoke-теста есть отдельный режим. Он измеряет DPI через HWND нативного окна и OpenFileDialog, сверяет масштаб WPF и WebView2 и проверяет оба физических размера окна. Масштабирование только содержимого WebView2 сохраняет ценность как проверка вёрстки. Для закрытия A03 требуются журналы режима native при DPI 120 и 144. [GetDpiForWindow в документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow)

### 20 ноября 2026 · первый блок P00–P02

- .NET 10.0.404 x64, централизованные версии NuGet, отдельные lock-файлы, строгий TypeScript и закрытый npm lock. Проверенный архив FFmpeg находится в локальных инструментах проекта. Системный PATH менять не требуется.
- Production загружает UI по внутреннему HTTPS-адресу через WebResourceRequested. Host отдаёт только известные типы ресурсов из сборки и зарегистрированные медиа по ID. Исходный каталог пользователя не монтируется. Запрос диапазона читает соответствующую часть файла. Сервер и сетевой порт не нужны.
- Команды обрабатывает подписка только верхнего документа. Проверяются точный адрес страницы, версия, UUID, набор и типы полей, разрешённая команда и тип переданных объектов. Для drop используется нативный CoreWebView2File. Прогресс текущей операции связан с UUID запроса, отмена адресуется этому UUID. Схема ошибок содержит безопасное сообщение и диагностический код. [Рекомендации Microsoft для WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)
- SQLite хранит отдельные таблицы project/media_asset. Первая миграция создаёт библиотеку, вторая добавляет ссылку на прокси. Метаданные и проект сохраняются транзакцией. Длительность хранится в целых микросекундах. JSON ffprobe сохраняет сведения о потоках, SAR/DAR, display matrix, цвете и частотах кадров при наличии. Средняя частота кадров сама по себе недостаточна для классификации VFR.
- Для строгого восстановления связи используется полный SHA-256. При открытии сначала проверяются размер и время изменения. Цена строгой проверки — последовательное чтение исходника при импорте и при relink. Операции проходят вне UI-потока с отменой.
- Прокси создаётся по явному запросу после ошибки проигрывателя. После проверки параметров через ffprobe временный MP4 переименовывается, его ID сохраняется отдельно от original_path. Обработка HDR в SDR требует проверенного tonemap и пока имеет отдельное сообщение.
- Локальная поставка — каталог win-x64 с EXE, DLL и UI. При наличии подготовленной пары инструментов Publish.ps1 включает её для этого ПК. Этот блок заканчивается импортом и просмотром. Установка ASR-моделей относится к P03.
