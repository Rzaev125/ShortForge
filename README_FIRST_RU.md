# ShortForge — пакет для начала разработки в Codex

**Обновление от 20 ноября 2026.** Исходный пакет ниже сохранён как история постановки. В папке уже есть Windows-приложение. Актуальные команды — в [README разработки](README.md), фактические проверки — в [STATUS.md](STATUS.md).

Дата: 20 ноября 2026. ShortForge — рабочее название, его можно заменить.

Это план, промпты и инструкции. Исходного кода приложения и готового EXE в архиве нет.
Цель: Windows-программа для личного использования, которая превращает длинные разговорные
видео в подборку вертикальных клипов с редактируемыми субтитрами и пакетным экспортом.

## Начать за 5 шагов

1. Распакуй содержимое этой папки, например, в `D:\Projects\ShortForge`.
   В корне должны лежать `AGENTS.md`, `PLANS.md`, `START_CODEX.txt` и папка `docs`.
2. По `docs/SETUP_WINDOWS.md` проверь .NET 10 SDK x64, Node.js 24 LTS x64, Git
   и WebView2 Runtime. Установленную .NET 9 удалять не надо. Docker для этого проекта не нужен.
3. Открой именно эту папку в локальном Codex на Windows. Если терминал Codex работает
   через WSL/Linux, сборку и запуск WPF проверяй из Windows PowerShell.
4. Скопируй **всё содержимое `START_CODEX.txt`** в первый запрос Codex.
5. Для следующих сессий используй промпт «Продолжить работу» из `PROMPTS_RU.md`.
   Codex должен обновлять `STATUS.md`, поэтому заново объяснять весь проект не потребуется.

Не вставляй весь архив текстом в чат: Codex прочитает файлы из выбранной папки.
Промпты этапов запускай по очереди. Промпт следующего этапа не нужен, если текущий ещё не завершён.

## Какой результат ожидать

- P00–P02: настоящее Windows-окно, интерфейс и импорт с реальными метаданными.
- P03–P06: распознавание, подбор моментов, правка клипов и оформление субтитров.
- P07: первые экспортированные MP4, которые можно просмотреть вне приложения.
- P08–P10: автоматическое кадрирование, восстановление очереди и проверенная сборка.

Это полноценный проект, а не задача «один промпт — идеальный редактор».
Оценку сроков делать после P02 и замера обработки на твоём компьютере.
Готовность считать по принятым этапам и проверкам, а не по числу файлов или красоте интерфейса.

## Что подготовить со своей стороны

- Windows-ПК. Исходный ориентир: i7-12700K / GTX 1660 Super; фактическое железо проверяется.
- Один свой разговорный ролик на 2–5 минут с хорошей речью для первой проверки.
- Позже: длинное видео 30–60 минут, запись с двумя людьми и проблемный ролик с шумом.
- Свободное место: запас под исходники, прокси, модели и экспорт; подробнее в SETUP.

API-ключи на старте не нужны. Локальный режим — основной. Облачный анализ текста
подключается отдельно и только после явного включения пользователем.

## Про модель Codex

Для архитектуры, процессов FFmpeg, временных шкал и аудита выбирай наиболее сильную
доступную модель для кода с высоким усилием рассуждения. Для небольших правок текста,
цветов и отступов достаточно стандартного уровня. Названия моделей зависят от доступного
списка в твоём Codex; этот пакет не привязан к конкретному названию.
Не запускай несколько агентов на одни файлы одновременно без отдельной договорённости.

## Важное различие

Видеоформат, экспорт и субтитры можно проверить технически. «Интересность» клипа и
качество смыслового выбора проверяются ещё и просмотром. Число клипов не гарантируется:
если в исходнике мало сильных моментов, программа должна честно предложить меньше.
