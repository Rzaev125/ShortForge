# Промпты для работы в Codex

Первый запуск: копируй START_CODEX.txt целиком. Далее используй нужный блок ниже.
Отправлять всё сразу не нужно. Агент читает актуальные файлы и продолжает существующий код.

## 1. Продолжить работу в новой сессии

```text
Продолжи ShortForge в текущей папке. Сначала прочитай AGENTS.md, STATUS.md, PLANS.md и релевантные docs. Проверь существующий код и git status, не начинай заново и не затирай мои изменения.

Выбери первый незавершённый этап с выполненными зависимостями. Реализуй его пользовательский сценарий, проведи проверки по docs/ACCEPTANCE.md и исправь найденные ошибки. Не ограничивайся анализом и предложением плана.

Не подменяй обработку mock-данными. Если интеграция заблокирована отсутствующим SDK/инструментом/моделью, точно укажи, чего не хватает, и продолжай независимую работу. Платные API и передачу видео/расшифровок в облако без моего включения не используй.

В конце обнови STATUS.md, критерии PLANS.md и решения. Отдельно перечисли: реализовано, проверено на Windows, не проверено, следующий шаг. Не считай этап завершённым без его acceptance criteria.
```

## 2. Проверить и подготовить окружение

```text
Проверь окружение ShortForge по docs/SETUP_WINDOWS.md. Сначала установи, в какой ОС работает твой терминал: Windows или WSL/Linux. Проверь .NET SDK (не только runtime), Node/npm, Git, WebView2, FFmpeg/ffprobe. Посмотри scripts/Check-Environment.ps1 перед запуском.

У меня ранее была .NET 9, Docker уже установлен. Ничего не удаляй и не переустанавливай без проверки. Для проекта нужен .NET 10 SDK x64; Docker не нужен. Дай короткий список только реально отсутствующих зависимостей с официальными ссылками и проверочными командами.

Подготовь конфигурацию проекта и воспроизводимые build/run команды для имеющихся зависимостей. Не объявляй проверку WPF пройденной в Linux. Обнови STATUS.md фактическими версиями и ограничениями.
```

## 3. Довести дизайн и интерфейс

```text
Доведи реальный интерфейс ShortForge по docs/DESIGN_SPEC.md. Сначала проверь существующий host/UI и текущее состояние функций. Сохрани стек WPF/WebView2 + React, не создавай отдельный лендинг.

Нужны удобные экраны: проекты, настройка анализа, обработка, результаты, редактор, очередь, настройки. Приоритет — редактор: клипы слева, вертикальное видео в центре, настройки справа, timeline снизу. Используй заданные tokens, ясную типографику, клавиатурный фокус и русский UI.

Работай с реальным состоянием backend. Недоступные функции объясняй, не симулируй успех. Проверь пустые состояния/ошибки/длинные названия, 1280×800 и 1440×900, DPI 125/150%. Покажи скриншоты проверенных экранов и укажи, были ли это Windows-окно или browser preview. Не переписывай рабочую обработку медиа ради внешнего вида.
```

## 4. P02 — настоящий импорт

```text
Реализуй или заверши P02 из PLANS.md: native выбор/drag-and-drop видео, реальный ffprobe JSON, SQLite-проект, thumbnail и preview/proxy fallback. Прочитай требования к безопасному мосту и media serving в docs/ARCHITECTURE.md.

Не передавай большие видео через base64/JS и не загружай их целиком в RAM. Исходник не изменяй. Учти отсутствие аудио, битый файл, rotation, VFR и разные audio streams. Проверь пути с пробелами, кириллицей и апострофом, сохранение/повторное открытие и relink отсутствующего источника.

Сгенерированный FFmpeg fixture допустим для smoke-test. Реальный импорт должен быть проверен на файле, а не mock-ответе. Обнови документацию и статус по фактическим проверкам.
```

## 5. P03 — распознавание и синхронизация

```text
Выполни P03 ShortForge. Подключи реальный whisper.cpp через изолированный process adapter. Проверь версию, --help и фактическую JSON-схему выбранной сборки. Не угадывай CLI-флаги.

Извлекай выбранную аудиодорожку, поддержи выбор языка, CPU fallback, отмену, кэш и переход к позиции видео по расшифровке. Начни с многоязычной small-модели; модель/скорость/память проверь на доступном ПК. Не переустанавливай драйверы и CUDA вслепую.

Проверь тишину, timestamp units, границы сегментов и слов. Не выдавай распределение слов по длительности предложения за точные word timestamps. Если нужна точная подсветка — проверь alignment; при плохих временах используй честный segment mode.

Проведи C-проверки из ACCEPTANCE. Если речевого материала нет, закончи техническую интеграцию и явно оставь качество ASR непроверенным. Обнови STATUS.md с реальными замерами.
```

## 6. P04 — качество выбора моментов

```text
Выполни P04. Построй кандидаты из реальных сегментов по паузам/предложениям, затем отдельный semantic-provider. Сначала используй настроенный локальный провайдер; облачный выключен по умолчанию. Если локальной модели нет, реализуй адаптер и понятную настройку, не притворяйся, что семантический ИИ уже работает.

LLM должен возвращать IDs исходных сегментов, объяснение и заголовок через валидируемую схему. Не принимать код, shell-команды, выдуманные цитаты и произвольные времена. Учти длинный контекст, overlap, дедупликацию, таймауты и prompt injection внутри расшифровки.

Предлагай меньше клипов, если качественных моментов мало. Отдельно маркируй ручной, эвристический и смысловой режим. Сравни качество с baseline на одном корпусе по D-проверкам docs/ACCEPTANCE.md. Не называй оценку «вероятностью вирусности». Запиши фактический результат и ограничения.
```

## 7. P05–P06 — редактор и субтитры

```text
Продолжи P05–P06 по PLANS.md. Реализуй правку In/Out, ручное создание клипа, crop/fit, undo/redo, autosave и редактирование текста. Исходную ASR сохраняй отдельно от пользовательских исправлений.

Для subtitle cues используй единую модель и точный source→clip time mapping. Поддержи три пресета, переносы, кириллицу/азербайджанские буквы, ASS burn-in и SRT. Текст безопасно экранируй; пользовательские пути не вставляй напрямую в FFmpeg filtergraph.

Сделай короткое render-preview тем же pipeline, что финальный экспорт. Проверь совпадение позиции/шрифтов/переносов, правильный rebase после trim и invalidation кэша. Не удаляй паузы внутри клипа, пока нет общей EDL для video/audio/captions/crop.

Не объявляй word highlighting точным без проверки таймингов. Обнови статус и приложи реальные проверочные артефакты.
```

## 8. P07 — MP4 и очередь

```text
Выполни P07 ShortForge. Подключи реальный FFmpeg export: 1080×1920 MP4 H.264/AAC, yuv420p, SAR 1:1, faststart, CFR 30, точные границы, текущий crop и субтитры. Используй исходник, а не низкокачественный proxy для финального рендера.

Сделай очередь с одним тяжёлым заданием по умолчанию, реальным progress, отменой process tree, retry и независимыми ошибками. NVENC разрешай после probe-encode, иначе CPU fallback. Не перезаписывай оригинал или существующий экспорт молча.

Записывай временный результат, проверяй ffprobe и только затем делай финальное переименование/Completed. Экспортируй три клипа и проверь их внешним проигрывателем, metadata, A/V sync и captions. Проверь F08, отсутствие аудио и отмену. Зафиксируй доказательства в STATUS.md.
```

## 9. P08 — кадрирование

```text
Реализуй P08 по PLANS.md. Подбери и зафиксируй совместимый face detector/tracker и лицензию, анализируй уменьшенные кадры. Нужны сглаженный crop, ограничения скорости, reset на scene cut, ручная коррекция и fallback при потере лица.

Не называй распознавание лица определением активного говорящего. Для двух людей пока допустим fit/static split с ручным выбором областей. Сохраняй trajectory и используй одинаковые данные в preview и export.

Проверь одного движущегося человека, два лица, отсутствие лица, перекрытие и смену сцены. Сравни preview и экспорт. Если нет подходящего материала, пометь качество tracking непроверенным.
```

## 10. P09–P10 — стабильность и сборка

```text
Выполни P09–P10. Сначала проверь корректность восстановления DB/jobs после сбоя и отмены, кэш, memory/disk usage на длинном видео и отсутствие потерянных child processes. Исправь критические дефекты по ACCEPTANCE.

Подготовь portable Windows x64 publish и проверенные Build.ps1/Run.ps1/Publish.ps1. Никаких node_modules/Vite в runtime, ключей/исходных личных видео в релизе. Явно опиши WebView2, FFmpeg, ASR-модели, сторонние лицензии и способ выбора путей. Self-contained .NET не устраняет native dependencies.

Проверь полный новый проект от импорта до трёх внешне воспроизводимых MP4 в Windows. Не называй Linux/browser-проверку Windows-проверкой. Дай инструкцию запуска, Known Issues и отчёт по всем gates. Ничего не публикуй и не загружай на платформы автоматически.
```

## 11. Независимая проверка фактической готовности

```text
Проведи аудит ShortForge по реальному коду и результатам запуска. Не принимай предыдущие отметки DONE на веру. Прочитай AGENTS.md, PLANS.md, STATUS.md и docs/ACCEPTANCE.md.

Для каждого этапа укажи: реализовано ли, как проверено, что не работает, есть ли mock/stub, отсутствующая интеграция или непроверенная Windows-зависимость. Сопоставь сохранённые клипы/субтитры/crop с реальными экспортами. Проверь отмену, восстановление, paths, секреты и неизменность исходника.

Исправь обнаруженные дефекты в разрешённой области и повтори затронутые тесты. Не делай большой рефакторинг без причины. Отчёт: таблица этапов, blockers с воспроизведением, сумма весов реально принятых DONE и точный следующий шаг. Не оценивай готовность по числу строк или файлов.
```

## 12. Если получилась только красивая оболочка

```text
Проверь ShortForge на фиктивные данные, задержки вместо задач, неработающие кнопки и ложный Completed. Сохрани удачный дизайн, но проведи один настоящий вертикальный сценарий: выбрать файл → ffprobe → реальная ASR → реальный клип → субтитры → реальный MP4.

Сначала восстанови отсутствующие зависимости по текущему этапу PLANS.md. Не расширяй интерфейс новыми декоративными экранами до исправления pipeline. Каждый шаг должен выдавать проверяемый результат. Не скрывай отсутствующий AI-провайдер/модель. Обнови STATUS.md честным списком готового и незавершённого.
```

## 13. Исправить конкретную ошибку

Заменить квадратные скобки своим текстом; ключи и приватные данные в логах убрать.

```text
В ShortForge ошибка: [текст/симптом].
Шаги: [1, 2, 3]. Ожидал: [результат]. Получил: [результат].
Среда: [Windows, версии если известны]. Лог/скриншот: [путь или приложенный файл].

Прочитай текущий STATUS.md и код затронутой функции. Воспроизведи, найди причину, исправь минимально необходимое и проверь регрессию. Не переписывай проект с нуля. Если проблема в окружении, покажи конкретную проверку и исправление. Обнови статус и сообщи результат реальных тестов.
```

## 14. Сохранить работу перед завершением сессии

```text
Подготовь передачу ShortForge следующей сессии. Сохрани текущие изменения без уничтожения моей работы. Обнови STATUS.md: активный этап, что работает, что не проверено, команды запуска/тестов, дефекты, точный следующий шаг. Обнови критерии PLANS.md и новые решения в docs/DECISIONS.md.

Если репозиторий использует git, покажи статус и сохрани логичный локальный commit согласно правилам репозитория; не делай push и не переписывай историю. Не отмечай непроверенные функции завершёнными. Следующая сессия должна продолжить без повторного планирования всего проекта.
```
